# Android APK Builder

Build complete Android Studio projects with Kotlin + Jetpack Compose and generate installable debug APK files, entirely from a natural language description.

## What this skill does

1. Takes a description of what the app should do
2. Generates a complete Android Studio project (build files, manifest, Kotlin sources, resources, theme)
3. Detects the local Android SDK and configures the project for it
4. Builds the project with Gradle and produces a debug APK
5. Copies the APK to the user's Desktop

## Environment

This skill is configured for this specific machine. If something doesn't match, adapt:

- **OS**: Windows 10, bash shell
- **Java**: JDK 17 at `C:\Program Files\Microsoft\jdk-17.0.18.8-hotspot`
- **Android SDK**: `C:\Users\user\AppData\Local\Android\Sdk`
- **Cached Gradle**: `~/.gradle/wrapper/dists/` (use whatever version is there)
- **Desktop**: `C:\Users\user\Desktop`

## Step 1 — Detect the build environment

Before generating any code, run the detection script to know what SDK platforms and build tools are available:

```bash
bash <skill-path>/scripts/detect_env.sh
```

This outputs the available `compileSdk` level, build-tools version, and the path to a cached Gradle binary. Use these values when generating the project files.

If the script fails or the SDK is missing, tell the user what needs to be installed.

## Step 2 — Design the app architecture

Keep it simple. The goal is a working app, not a showcase of architecture patterns.

**Always use:**
- Kotlin
- Jetpack Compose + Material 3
- Single Activity with Navigation Compose
- Dark theme by default (dark background, high contrast, large text)
- DataStore Preferences for any local persistence
- 100% offline — no network, no backend, no auth, no cloud

**Never add:**
- Heavy frameworks (Hilt, Room, Retrofit) unless the user specifically asks
- Animations or decorative elements unless requested
- Accounts, login, cloud sync
- Complex navigation patterns — flat is better

**Project structure:**
```

├── settings.gradle.kts
├── gradle.properties

│   ├── proguard-rules.pro
```

## Step 3 — Generate the project files

### Build files

**settings.gradle.kts** — standard pluginManagement + dependencyResolutionManagement with google() and mavenCentral().

**build.gradle.kts (root)** — declare AGP and Kotlin plugins with `apply false`. Use AGP 8.2.2 and Kotlin 1.9.22 as defaults (they're widely compatible). If the detected SDK is very new, you may need to bump AGP — but prefer the older stable versions.

**app/build.gradle.kts** — key settings:
- `compileSdk` and `targetSdk`: use the value detected in Step 1
- `minSdk = 26` (Android 8.0+, good coverage)
- `composeOptions.kotlinCompilerExtensionVersion = "1.5.10"` (matches Kotlin 1.9.22)
- Compose BOM: `2024.02.00`
- Navigation Compose: `2.7.7`
- DataStore: `1.0.0`
- Material Icons Extended for icon variety

**gradle.properties** — include `android.suppressUnsupportedCompileSdk=<compileSdk>` if compileSdk > 34 (to suppress AGP warnings).

**local.properties** — use escaped backslashes for the SDK path on Windows:
```properties
sdk.dir=C:\\Users\\user\\AppData\\Local\\Android\\Sdk
```

### Manifest

Portrait only, no special permissions needed for offline apps. Use adaptive icon resources.

### Theme

Default to a dark color scheme:
- Background: `#121212`
- Surface: `#1E1E1E`
- Cards: `#2A2A2A`
- Primary text: `#EEEEEE`
- Secondary text: `#B0B0B0`
- Accent colors as needed

Large typography as default. The user's app should be readable at a glance.

### App icon

Create a simple vector-based adaptive icon. Use a letter or simple shape related to the app's purpose on a dark background.

## Step 4 — Generate the Gradle wrapper

The project needs `gradlew`, `gradlew.bat`, and `gradle-wrapper.jar`. These are binary/generated files that can't be written by hand. Use the detection script's output to find a cached Gradle binary, then run:

```bash
cd <project-dir> && "<cached-gradle-path>" wrapper --gradle-version 8.4
```

If no cached Gradle is found, check if `gradle` is on PATH. If neither works, tell the user to open the project in Android Studio (which generates the wrapper automatically).

## Step 5 — Build the APK

```bash
cd <project-dir> && ./gradlew assembleDebug 2>&1
```

This can take 3-10 minutes on first run (downloads dependencies). Set a generous timeout (600s).

The APK lands at: `app/build/outputs/apk/debug/app-debug.apk`

If the build fails:
- Read the error output carefully
- Common issues: missing SDK platform (install it), version mismatches (adjust compileSdk or AGP), Compose compiler incompatibility (match Kotlin and compiler extension versions)
- Fix the issue in the source files and rebuild

## Step 6 — Deliver

Copy the APK to the Desktop with a clear name:

```bash
cp <project-dir>/app/build/outputs/apk/debug/app-debug.apk ~/Desktop/<AppName>.apk
```

Tell the user:
- Where the APK is
- How to install it on their phone (transfer via USB/email/Drive, enable unknown sources, install)
- That the full project is at `<project-dir>/` if they want to open it in Android Studio

## Common patterns

### Navigation with bottom bar
For apps with multiple screens, use a persistent bottom bar with key actions (Home, primary action, settings toggle). Keep the nav graph flat — avoid nested navigation.

### Persistent preferences
Use DataStore for simple key-value storage (settings, last state, favorites). Don't use Room unless the app genuinely needs a relational database.

### Large text / accessibility
Default to large touch targets (min 56dp), generous padding (16-20dp), and text sizes of 17-20sp for body content. Use font scaling if the user might need different text sizes.

### Content-heavy apps
For apps where the main value is text content (guides, checklists, reference material), embed all content directly in Kotlin composables. Don't over-engineer with JSON data files or string resources for content that won't be translated.
